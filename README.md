# Выгрузка выбранных папок Яндекс Диска

> **Скрипт и интерфейс собраны на коленке под одну конкретную задачу:** вытащить файлы с нестабильно работающего Яндекс Диска, не застревая на недоступных файлах. Свою функцию выполняют, но это не отполированный универсальный продукт. Используйте отдельную папку назначения и не считайте эту выгрузку единственной резервной копией важных данных.

Python 3.9+ и rclone. TUI работает на macOS/Linux; `download.py` можно запускать на Windows с Python/rclone в PATH. Два режима: **WebDAV с паролем приложения** и **REST API с токеном Полигона Яндекса**. Скрипт **ничего не удаляет на Диске**, не использует `sync`, не меняет общую конфигурацию rclone.

## Быстрый старт: TUI

На macOS:

```bash
brew install python rclone
git clone https://github.com/Lynxy039/yandex-disk-backup.git
cd yandex-disk-backup
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
./get-from-yadisk.sh
```

На Linux вместо Homebrew установите Python, python3-venv и rclone средствами вашего дистрибутива.

**JSON вручную редактировать не нужно.** Вкладка «Настройки» позволяет:

- выбрать WebDAV или REST API, ввести логин и скрытый пароль приложения / OAuth-токен;
- при желании включить шифрование пароля или токена мастер-паролем либо отключить его;
- добавить, изменить и удалить пары папок «на Диске → на компьютере»;
- раскрыть настройки параллельности, повторов и пути журналов;
- сохранить настройки или сохранить их и сразу начать выгрузку.

При первом сохранении создаётся `settings.json` с правами `600`; при следующем запуске данные загружаются автоматически. Пароль или токен замаскирован на экране. **По умолчанию секрет хранится открытым текстом; шифрование мастер-паролем включается отдельно.** Кнопка «Сохранить и начать» также сохраняет настройки. Для WebDAV нужен пароль приложения, для REST — токен Полигона; основной пароль аккаунта не используется.

Вкладка «Выгрузка» показывает очередь папок, фазы (скачивание/проверка), скорость, активные файлы, **секунды без новых данных и без новых файлов списка**, количество скачанных/готовых/отложенных/неудачных файлов и события. Обход папки и скачивание идут параллельно; «Известно файлов» растёт по мере обхода. Данные обновляются дважды в секунду. Прогресс — **обработанные файлы текущего прохода**, включая отложенные; 100% прохода не означает, что всё скачано. Итоговые списки находятся в отчётах. ETA не вычисляется: при недоступных файлах она вводила бы в заблуждение.

Управление: **Tab / Shift+Tab** — переход между полями, **Ctrl+S** — сохранить, **F5** — запустить, **F8** — остановить с сохранением отчётов, **Ctrl+Q / Ctrl+C** — выйти. При выходе во время работы нужно подтвердить остановку. Кнопки и вкладки работают мышью; длинная форма прокручивается. Редактирование заблокировано во время выгрузки. После завершения/остановки можно вернуться к настройкам и запустить снова; скачанное будет пропущено по правилам сравнения размеров.

Другой файл настроек:

```bash
./get-from-yadisk.sh /путь/к/настройкам.json
# или напрямую:
.venv/bin/python tui.py /путь/к/настройкам.json
```

TUI требует интерактивного терминала. Закрытие терминала/выключение компьютера не равнозначно штатной остановке. Для фонового запуска без интерфейса используйте CLI ниже.

## REST API: токен Полигона вместо WebDAV

Это дополнительный режим в том же скрипте, а не новая программа. Для скачивания используется native-бэкенд `yandex` в rclone, как в [статье о выгрузке 1,8 ТБ](https://habr.com/ru/articles/1095554/). Список читается напрямую через REST API постранично, чтобы очередь не ждала всю большую папку. Для описанного в статье обхода HTTP 410 нужен **токен Полигона**, а не токен, полученный обычной авторизацией через `rclone config`.

После обновления кода обновите зависимости: `.venv/bin/python -m pip install -r requirements.txt` (для постраничного REST-листинга нужен HTTPX).

### Получение токена и запуск в TUI

1. Откройте [Полигон Яндекс Диска](https://yandex.ru/dev/disk/poligon/) в браузере и войдите в нужный аккаунт.
2. Нажмите **«Получить OAuth-токен»**, подтвердите доступ, если потребуется, и скопируйте токен. Не публикуйте его и не отправляйте в чат.
3. Перед запуском REST остановите прежнюю выгрузку через **F8**, выйдите из старого TUI и запустите его заново. **Не запускайте WebDAV и REST одновременно в одну папку назначения.**
4. В поле «Способ подключения» выберите **REST API · токен Полигона**, укажите логин того же аккаунта и вставьте токен в соответствующее скрытое поле. Логин используется для разделения локальных индексов; REST авторизуется токеном, принадлежность аккаунту скрипт автоматически не проверяет.
5. Оставьте прежние пары папок, при желании включите мастер-пароль и запустите. Уже скачанные файлы с совпадающим размером будут пропущены после обнаружения в REST-списке.

При смене режима поле секрета переключается: пароль WebDAV не подставляется вместо OAuth-токена. **При сохранении из TUI в файле остаются только учётные данные выбранного режима**; для возврата к другому режиму потребуется его пароль/токен. Если хотите сохранить оба варианта настроек, используйте отдельные приватные файлы.

### Отдельный файл настроек и CLI

Для нового файла, не заменяя рабочий `settings.json`:

```bash
cp -n settings.rest.example.json settings.rest.json
chmod 600 settings.rest.json
./get-from-yadisk.sh settings.rest.json

# После заполнения логина, токена и папок — запуск без интерфейса:
./get-from-yadisk.sh --cli settings.rest.json

# Необязательно: зашифровать токен мастер-паролем без запуска выгрузки:
./get-from-yadisk.sh --cli settings.rest.json --encrypt-password
```

В REST-примере указаны `backend: "rest"`, поле `oauth_token`, 16 потоков, `idle_timeout: 8`, `file_timeout: 60`. Это наши агрессивные пофайловые лимиты, **не точная копия таймаутов из статьи**. Получение ссылки REST API тоже занимает время и входит в лимит бездействия; если доступные файлы не успевают начать отдавать данные, увеличьте `idle_timeout`, например до 15–30 секунд.

### Важные отличия и безопасность

- Для листинга токен передаётся в заголовке `Authorization` HTTPS-запроса, для скачивания — через `RCLONE_YANDEX_TOKEN`, не аргументом команды и не файлом `rclone.conf`. Как в статье, OAuth JSON содержит `refresh_token: "unused"` и `expiry` в 2099 году. Это только заглушки для rclone: **реальный срок жизни токена они не продлевают**. При истечении/отзыве токена нужно получить новый.
- Токен Полигона даёт широкий доступ к Диску. Наши команды только читают источник, но украденный токен может позволить изменять данные. После выгрузки отзовите доступ Полигона в настройках приложений Яндекс ID.
- Мастер-пароль шифрует `oauth_token` в поле `oauth_token_encrypted`; включение и отключение такие же, как для пароля WebDAV.
- REST-листинг идёт страницами до **1000 объектов** через асинхронный HTTPX. Первая страница сразу поступает в очередь; оставшиеся страницы и подпапки обходятся параллельно со скачиванием. `rclone lsjson` для REST-листинга не используется: он может буферизовать большую папку до завершения всех страниц. F8 отменяет ожидающий HTTP-запрос без фонового потока.
- REST имеет **отдельный индекс**, чтобы не смешивать непроверенные учётные записи разных режимов. Индекс WebDAV не удаляется; локальные готовые файлы не перескачиваются, если размеры совпадают.
- Здесь по-прежнему отдельный процесс rclone на файл. Команда автора с 64 передачами в одном процессе и `--tpslimit 20` не эквивалентна нашим 64 процессам. **Общего лимитера API-запросов в этой версии нет**; начинайте с умеренной параллельности.
- Итоговая проверка и пропуск готовых файлов остаются **по размеру**. Полная сверка MD5 как в статье в этой версии не добавлена.
- Перенос «безлимитных» фото в обычные папки не выполняется: это меняет Диск и может занять тарифное место. Скачиваются только файлы, доступные выбранному API в обычных папках.

## Как получить пароль приложения Яндекса («ключ» для WebDAV)

1. Откройте [Яндекс ID → Пароли приложений](https://id.yandex.ru/security/app-passwords) и войдите в нужный аккаунт. Этот раздел также доступен из настроек безопасности Яндекс ID.
2. Нажмите создание нового пароля приложения. Если предлагается выбрать сервис, выберите **Диск**. Назовите пароль, например, `YandexDiskBackup`.
3. Скопируйте выданный пароль: обычно он показывается только при создании. **Это не основной пароль аккаунта и не OAuth-токен.**
4. В TUI укажите логин Яндекса и вставьте этот пароль в поле «Пароль приложения для Яндекс Диска». Для ручного JSON это поле `app_password`.
5. По желанию включите локальное шифрование мастер-паролем по инструкции ниже. Мастер-пароль придумываете вы; Яндексу он не отправляется.

Отозвать пароль приложения можно на той же странице Яндекс ID. Если забыли мастер-пароль, отзовите старый пароль приложения, создайте новый и настройте его заново. Доступность WebDAV зависит от аккаунта, тарифа и состояния сервиса; сам пароль не снимает ограничения Яндекса.

## Мастер-пароль (необязательно)

Старые настройки с обычным `app_password` продолжают работать. Шифрование включается только по вашему выбору; скрипт не меняет существующий файл автоматически.

### В TUI

1. Выберите способ подключения, заполните логин, пароль приложения или токен Полигона и папки.
2. Раскройте блок **«Мастер-пароль (необязательно)»**, включите «Шифровать пароль/токен мастер-паролем».
3. Введите мастер-пароль дважды и сохраните. Минимум — **12 символов**, лучше несколько случайно выбранных слов. Одно словарное слово вроде «АЗБУКА» слишком слабое.
4. При следующем открытии поле пароля/токена будет пустым — оставьте его пустым и введите мастер-пароль перед сохранением или запуском. Повторять его во втором поле не нужно. Если заменяете пароль/токен новым, мастер-пароль нужно подтвердить снова.
5. Чтобы **отключить шифрование**, введите текущий мастер-пароль, снимите галочку и сохраните. Пароль/токен снова будет храниться открытым текстом.

Неверная фраза или несовпадающее подтверждение не перезаписывают настройки. Для включения функции в уже открытом старом TUI сначала штатно завершите выгрузку и перезапустите интерфейс. Не меняйте файл через CLI одновременно с открытым TUI: последующее сохранение из старого окна может затереть изменения.

### В CLI

После заполнения настроек, из интерактивного терминала:

```bash
.venv/bin/python -m pip install -r requirements.txt

# Включить шифрование: спросит новую фразу и подтверждение.
./get-from-yadisk.sh --cli --encrypt-password

# Обычный запуск: спросит мастер-пароль, если шифрование включено.
./get-from-yadisk.sh --cli

# Отключить шифрование: спросит текущую фразу и сохранит пароль открытым текстом.
./get-from-yadisk.sh --cli --decrypt-password
```

`--encrypt-password` и `--decrypt-password` только меняют настройки, **не запускают выгрузку и не обращаются к Яндексу**. Повторный `--encrypt-password` позволяет сменить мастер-пароль: сначала вводится текущий, затем новый дважды. При другом файле настроек укажите его после `--cli`, перед флагом.

### Что защищено и что нет

- Используется **AES-256-GCM**, ключ получается из фразы через **scrypt** (`N=131072`, `r=8`, `p=1`, около 128 МиБ памяти). При каждом сохранении генерируются случайные соль и nonce; изменение шифротекста обнаруживается.
- В JSON вместо `app_password` хранится `app_password_encrypted`, а для REST вместо `oauth_token` — `oauth_token_encrypted`: версия формата, соль, nonce и шифротекст. **Мастер-пароль и ключ не записываются на диск, не передаются в аргументах команд и не сохраняются в журналах.** Логин, пути и остальные настройки не шифруются.
- В TUI фраза остаётся в скрытом поле до закрытия окна, а пароль приложения / токен нужен в оперативной памяти во время работы. Движку он передаётся по отдельному stdin-pipe, rclone — через окружение. От вредоносных программ с доступом к вашему процессу или администраторскими правами это не защищает. Гарантированного стирания секретов из памяти и защиты от системных дампов/swap нет.
- При включённом шифровании фоновый запуск без участия человека не поддерживается: нужно ввести мастер-пароль. Не передавайте его аргументом команды, через файл или переменную окружения.
- **Забытый мастер-пароль восстановить нельзя.** Создайте новый пароль приложения или токен Полигона и настройте его заново. Слабую фразу можно перебрать по украденному файлу.
- Шифрование не удаляет старые открытые копии настроек из резервных копий, истории Git или с диска. Если пароль уже утёк, отзовите его в Яндекс ID.

## 1. Настройки вручную (необязательно)

На macOS установите зависимости, если их нет:

```bash
brew install python rclone
```

Создайте свой файл настроек:

```bash
cp settings.example.json settings.json
chmod 600 settings.json
```

Откройте `settings.json` в редакторе и замените:

- `backend` — `webdav` (по умолчанию, в том числе для старых файлов без поля) или `rest`;
- `login` — логин Яндекса, используется также для разделения индексов;
- `oauth_token` — токен Полигона для REST; при шифровании заменяется на `oauth_token_encrypted`;
- `app_password` — **пароль приложения для Диска**, не основной пароль. Как создать — см. инструкцию выше. При включённом шифровании поле заменяется на `app_password_encrypted`; формировать его вручную не нужно;
- `jobs` — любое количество пар `source` / `destination`;
- `logs_dir` — папка журналов, по умолчанию `logs` рядом с настройками;
- `transfers` — число одновременно скачиваемых файлов, по умолчанию 2;
- `idle_timeout` — максимум секунд без новых данных **на отдельном файле**, по умолчанию **8**;
- `file_timeout` — минимальный общий лимит одной попытки, по умолчанию **20 секунд**;
- `retry_passes` — дополнительные проходы по отложенным файлам **после остальных**, по умолчанию **2** (всего до трёх попыток); `0` — только быстрый первый проход;
- `listing_timeout` — максимум секунд **без новых элементов списка** во время обхода папки, по умолчанию **180**. Это не общий лимит: обход может идти часами, пока появляются новые файлы.

Старые поля `retries` и `low_level_retries` больше не используются; TUI удалит их при следующем сохранении. Для прежнего JSON без новых полей автоматически применяются указанные значения по умолчанию.

Пример одной пары:

```json
{
  "source": "/Фото/Отпуск 2025",
  "destination": "/Volumes/Backup/Yandex/Отпуск 2025"
}
```

Содержимое выбранной папки помещается **непосредственно в destination**:

```text
Диск: /Фото/Отпуск 2025/День 1/IMG_001.jpg
ПК:   /Volumes/Backup/Yandex/Отпуск 2025/День 1/IMG_001.jpg
```

Подпапки любой глубины и пустые папки сохраняются. Скачиваются все типы файлов, включая видео. `source: "/"` означает весь Диск, доступный выбранному способу подключения. Имена папок должны соответствовать реальным папкам, а не названию альбома в интерфейсе.

`destination` может быть абсолютным, начинаться с `~` или быть относительным к файлу настроек. В JSON на Windows используйте `/`, например `D:/YandexBackup/Фото`. Папки назначения разных заданий не должны пересекаться. Логи должны находиться отдельно от них.

**Для внешнего диска сначала убедитесь, что он подключён.** Иначе указанный путь может быть создан на системном диске.

Без мастер-пароля пароль/токен хранится в JSON открытым текстом; с мастер-паролем — в зашифрованном виде. **В обоих случаях не отправляйте настройки в чат и не публикуйте**: там остаются логин и личные пути. `settings.json` исключён из Git; на macOS/Linux скрипт требует права `600` (доступ только владельцу). Пароль передаётся rclone через окружение, не через аргументы командной строки; в отчёты и `rclone.conf` не записывается. Не запускайте под недоверенным пользователем/на общем сервере.

## 2. Неинтерактивный запуск (CLI)

```bash
./get-from-yadisk.sh --cli
```

Или с другим набором настроек:

```bash
python3 download.py /путь/к/настройкам.json
```

Папки обрабатываются по очереди. Обход папки (для WebDAV — `rclone lsjson --recursive`, для REST — прямые API-страницы до 1000 объектов) и скачивание идут **параллельно**: каждый найденный файл сразу попадает в очередь и начинает грузиться, ждать завершения списка не нужно. Если обход оборвался (таймаут, 5xx, обрыв соединения), найденные файлы **остаются в очереди** и будут скачаны, а папка получит статус `failed` с пометкой «список неполный» — это честная отметка, а не ложный успех.

Каждый найденный файл сразу дописывается в сохраняемый индекс SQLite (`logs/.inventory/<хеш>.sqlite3`, отдельно для логина, исходной папки, назначения и режима подключения). При следующем запуске известные пути ставятся в очередь **сразу, до начала обхода**, — даже если сервер снова не отдаст список. Устаревшие пути удаляются из индекса только после полностью успешного обхода.

Далее работает пофайловая очередь. На каждый файл запускается отдельный `rclone copyto`, **без внутренних повторов**. Если временный файл не растёт `idle_timeout` секунд, попытка прекращается, процесс завершается, поток получает следующий файл. Ошибки HTTP также сразу откладывают файл. Повторы идут только после завершения всего текущего прохода **этой папки**. Окончательный отказ одного файла не блокирует остальные файлы и папки.

Общий предел попытки: `max(file_timeout, idle_timeout + размер_в_МиБ)` секунд. Для небольших фото это обычно 20 секунд, для больших видео — больше; лимит бездействия всё равно остаётся 8 секунд. Даже очень медленная, но не зависшая загрузка может превысить общий предел — увеличьте `file_timeout` при необходимости. Завершение процесса/удаление временного файла добавляет небольшое время к лимиту.

В терминале виден прогресс; подробные события сохраняются в логах. `Ctrl+C` останавливает запуск, сохраняя журналы и статус `interrupted`. Жёсткое выключение питания не позволяет гарантировать финальную запись отчёта.

Для долгой выгрузки на Mac без засыпания:

```bash
caffeinate -i ./get-from-yadisk.sh
```

## 3. Повторный запуск и проверка

Запустите **ту же команду**. Известные пути из индекса (`logs/.inventory`) встают в очередь сразу, до обращения к серверу. Готовые файлы с совпадающим размером будут пропущены **без сетевого запроса к этому файлу**, отсутствующие или отличающиеся — поставлены в очередь. Оборванный файл скачивается заново. Каждая попытка пишет в отдельный `.yadisk-*.part` рядом с назначением. Только после успешного завершения rclone и совпадения размера временный файл атомарно заменяет готовый. При таймауте/штатной остановке временный файл удаляется, старый готовый файл не меняется.

Выделите отдельные папки под резервную копию: существующий файл с тем же именем и другим размером будет заменён. Посторонние файлы не удаляются.

После очереди локально проверяются наличие и размеры **по известному списку** (`manifest.json`), без повторного обращения к зависающему серверу. Это **не криптографическая проверка содержимого**: повреждение с сохранением размера не обнаружится. Не меняйте исходные папки во время выгрузки: список отражает состояние на момент обхода, а не на момент завершения. При неполном обходе часть файлов может остаться неизвестной — индекс пополнится при следующем запуске. Небезопасные относительные пути и символические ссылки в назначении отклоняются.

## 4. Логи и списки файлов

Каждый запуск создаёт отдельный каталог:

```text
logs/
  .inventory/<хеш>.sqlite3        сохраняемый индекс найденных путей (на каждую пару папок)
  .download.lock                  блокировка одновременных запусков
  YYYYMMDD-HHMMSS-ffffff/
    summary.json                  общий статус и результаты папок
    01/                           первая пара из jobs
      summary.json                статус, полнота обхода, результаты и счётчики
      manifest.json               итоговый список известных файлов и подпапок
      manifest.jsonl              каждый найденный файл по мере обнаружения (источник: обход или индекс)
      listing.jsonl               ошибки списка: stderr rclone или ошибки REST API
      copy.jsonl                  попытки, таймауты, отложенные файлы и статистика
      check.json / check.jsonl    итог локальной проверки размеров по manifest
      downloaded.jsonl            успешно скопированные файлы (пишется сразу)
      results.jsonl               итог каждого известного файла, число попыток
      failed.jsonl                нескачанные/непроверенные файлы и причины
      present.txt                 файлы, совпавшие при итоговой проверке по размеру
      failed.txt                  сводка известных проблем: причина + путь
      missing.txt                 отсутствующие локально файлы
      different.txt               файлы с отличающимся размером
      errors.txt                  файлы, которые не удалось проверить
    02/                           вторая пара и т. д.
```

Пути в файловых списках относительны выбранной исходной папке. `downloaded.jsonl` содержит JSON-объект на строку: время, путь, размер, номер попытки. Здесь нет уже готовых файлов, пропущенных при повторном запуске — они находятся в `present.txt` и `results.jsonl`. Журнал `copy.jsonl` также сохраняет временные ошибки, после которых файл мог успешно скачаться. Статус `deferred` означает отложенную попытку, а не окончательный отказ. При остановке `failed.jsonl` включает также известные, но ещё не обработанные файлы. JSONL сохраняет имена файлов без неоднозначности, в том числе с переводами строк; текстовые списки — только для удобного просмотра.

**Пустой `failed.txt` сам по себе не означает успех.** При неполном обходе сервер мог не вернуть часть файлов. Проверяйте `summary.json`: полная выгрузка — только `status: "ok"`, `manifest_complete: true` и `verification_complete: true`. Поле `known_files_verified: true` при `manifest_complete: false` означает: всё известное скачано и проверено, но часть папки могла остаться неисследованной — запустите повторно, индекс и новый обход дополнят друг друга. Ошибки обхода — в `listing.jsonl`, ошибки файлов — в `copy.jsonl` и `failed.jsonl`.

Коды завершения: `0` — всё скопировано и проверено, `1` — ошибка, `130` — прерывание пользователем. Два запуска с одним `logs_dir` запрещены блокировкой `.download.lock`. После аварийного отключения удалите её вручную **только убедившись, что прежняя выгрузка не работает**. Для разных конфигураций не запускайте запись одновременно в одни и те же папки назначения.

## Ограничения Яндекса

WebDAV может быть ограничен тарифом, REST — правами/сроком действия токена; оба способа могут быть временно недоступны. Скрипт не может гарантировать доступность серверов. Альбомы и фото из безлимитной автозагрузки, которые не представлены обычными папками выбранного API, этим способом могут быть недоступны — **это не гарантированная выгрузка всего раздела «Фото»**. Публичные ссылки здесь не поддерживаются.

Источники исходного исследования (октябрь 2026):

- Обсуждение HTTP 410 в rclone, WebDAV как временный вариант и опыт пользователей: https://github.com/rclone/rclone/issues/10067 — блокировка общего client_id является гипотезой участников, не установленным фактом.
- Ограничения массового скачивания в веб-интерфейсе: https://3dnews.ru/1149774/yandeks-ogranichil-skachivaniya-s-diska-chtobi-snizit-nagruzku-na-utselevshie-datatsentri
- Официальная инструкция WebDAV: https://yandex.ru/support/yandex-360/customers/disk/web/ru/webdav
- REST через токен Полигона и заглушку refresh_token: https://habr.com/ru/articles/1095554/ ; практические инструкции автора: https://github.com/KenGuru66/yandex-disk-rescue

## Тесты без доступа к аккаунту

```bash
.venv/bin/python -m unittest -v
```

Тесты используют временные локальные папки, установленный rclone, локальный WebDAV-сервер и headless-режим Textual; аккаунт Яндекса не нужен. Проверяются: скачивание файла до конца обхода, обрыв списка без потери найденного, перезапуск из индекса при недоступном сервере, изоляция индекса между аккаунтами, таймаут зависшего процесса и переход к следующему файлу, отложенные повторы, защита готового файла и проверка размера, структура подпапок, ввод/сохранение настроек, отображение ошибок, связка TUI → движок → локальный rclone, остановка и отчёты. Для мастер-пароля проверяются шифрование/расшифровка, случайность соли и nonce, неверная фраза и повреждённые данные, включение/отключение без запуска выгрузки, сохранность файла при ошибке и запуск TUI → движок через pipe без паролей в аргументах. REST проверяется через локальный HTTPS-стенд: постраничный HTTPX-листинг и настоящий native-бэкенд rclone для скачивания, OAuth-заголовок, загрузка первого файла до завершения второй страницы, повторный запуск без повторной загрузки, отсутствие refresh/изменяющих запросов и токена в отчётах. Отдельно проверяются обрыв следующей страницы без потери первой, пустые подпапки, небезопасные пути, неполные ответы и немедленная отмена запроса. Для self-signed стенда проверка сертификата отключается **только в тесте**, рабочие запросы проверяют TLS как обычно. Ни один из этих тестов не требует настоящего токена и не подтверждает доступность конкретного аккаунта Яндекса. Тесты движка без Textual: `python3 -m unittest test_download test_transfers test_discovery test_webdav test_passwords test_rest test_rest_native test_rest_listing -v` (для шифрования и REST HTTPS-стенда нужен `cryptography`).
